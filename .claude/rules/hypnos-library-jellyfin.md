# Hypnos: Library tab, Jellyfin, subtitles and offline downloads

Moved out of `CLAUDE.md`.

## Streaming quality (Library titles)

`LibraryStreamQuality` (`Services/Library/LibraryStreamQuality.swift`): **Auto** (default: original, i.e. direct play or a full-quality remux, stepped down when the stream can't keep up), **Always Direct Play** (original, never stepped) and six bitrate caps (40/30/20/10/4/1.5 Mbps: 4K, 1440p, 1080p twice, 720p, 480p; H.264 HLS with `MaxWidth`/`MaxHeight`; a cap at or above the file's own bitrate plays the original). One saved preference (`library.streamQuality`), set from the detail page's gauge button before Play or from the player's Quality menu; `JellyfinLibrary.streamPlan(itemId:quality:)` builds the stream, and `playbackRoute(for:)` uses the preference, so tvOS's system player honours fixed caps too (the Mac plays Library titles in the video window). The level now playing is read back off the URL's `MaxStreamingBitrate` (`level(ofStream:)`), so it survives renewed play sessions and restored windows. Auto runs only in the video window (`VideoWindowModel+StreamQuality`): both AVPlayer paths report `waiting` (`.waitingToPlayAtSpecifiedRate`, `RAVEPlaybackState.waiting`), and `StreamStallMonitor` steps down after no first frame in 12 s, one 6 s stall, or 10 s of stalls within 90 s, ignoring the 4 s after a seek, resume or stream switch and the 15 s after a step. The step is announced by `StreamQualityNotice`, hung under the window beside the skip button (the ornament `prompt` slot). The object-audio film player has its own picture tiers (below). With **Play MKV Files on This Device** on (`JellyfinLibrary.remuxesOnDevice`, Jellyfin settings, on by default) an MKV the native player can't open plays as its own file, remuxed on the device as a Stash MKV is ("Matroska remux" in `hypnos-video-window.md`), rather than as Jellyfin's HLS remux: every audio track, the original sound, no server work. The server's remux is the plan's reserve `transcodeURL`, for a file the device declines.

**The player's Quality menu lists what the title can be streamed at** (2026-10-23), not the whole ladder: `LibraryStreamQuality.offered` (RAVEMediaCore) drops levels above the source's picture class (`pictureClass`: by either side, so a 1920×800 film is 1080p) and levels whose cap is above the source's bitrate (they'd play the original). The window asks `JellyfinLibrary.sourcePicture` (PlaybackInfo's video stream width/height/frame rate and the source bitrate) once per title (`loadLibrarySource`). A saved level the title doesn't offer checks Original (that's what plays); the badge shows what plays ("1080p" for an original 1080p film, never the preference's "4K"). The detail page's gauge still sets the cross-title preference from the full ladder.

## Jellyfin 12.x

Jellyfin 12 dropped the legacy auth spellings: the `X-Emby-Token`/`X-Emby-Authorization` headers and the `api_key` query answer 401/400. Send `Authorization: MediaBrowser … Token="…"` and `ApiKey=`, which 10.11 also accepts. The plugin targets 12.2 / .NET 10 and doesn't load on 10.11, so a server runs the plugin build for its version. The dev script runs 12.2 (Docker and native; native with jellyfin-ffmpeg's portable build, which has the Dolby Vision filters Homebrew's lacks).

## Subtitles

Every player draws subtitles itself with RAVEUI's `RAVESubtitleOverlay`; none of them has an `AVPlayerItem` whose legible output could. `SubtitleController` (`Services/Subtitles/`, one per `FilmSession` and per `VideoWindowModel`) lists an item's tracks, fetches and parses the chosen one and holds the timing offset; `SubtitleSource` is where tracks come from: Jellyfin's `Videos/{id}/{source}/Subtitles/{n}/Stream.vtt` (converts sidecar SRT/ASS and embedded text streams). Embedded PGS comes as `Stream.pgssub`, a `.sup` file decoded by `PGSSupFile` with Vergence's PGS decoder (10.11 can't convert images to text); the first request for an embedded track extracts every subtitle stream from the whole file, minutes on a UHD remux, and 15–90 s for an Archer episode on a network share. So an embedded **text** track (`LibrarySubtitleTrack.isEmbedded`) is **streamed from the plugin** instead (`JellyfinLibrary.subtitleStream`, the plugin's `FilmSubtitles/{id}/{index}.vtt?startSeconds=`; `JellyfinPlugin/README.md` → Subtitles): ffmpeg seeks to the playhead and the cues arrive as the file reads, `SubtitleController` shows them as they come (`SubtitleSource.progressive`, the owner's `playhead`), restarts on a seek outside what has arrived, and fills in the stretch before the run once it reaches the end. A server without the plugin answers 404 and the track is fetched whole as before; sidecars and PGS always are. The `-LibraryHarness` check `streamedSubtitles` covers resumed / from-start / kept runs on the dev seed's `Subtitle Window (2026)` (ten minutes of MKV with an embedded SRT). Other image formats (VobSub, DVB) are listed but disabled or Stash's sidecar captions (`scene.captions` + `paths.caption?lang=&type=`, served as WebVTT). An MKV/WebM that plays remuxed on the device adds its own tracks (`SubtitleSource.matroska`, read near the playhead from the file itself; see "Matroska remux" in `hypnos-video-window.md`). A video file on the device (Local library, shared files) gets `SubtitleSource.localFile` (`LocalSubtitleSource.swift`): SRT/VTT files beside it whose name starts with the video's (`Film.fr.forced.srt`; the words in between give language and flags), plus `tx3g` text tracks inside an MP4/MOV, read with AVAssetReader and handed to the parser as SubRip (other embedded formats list as unsupported). `SubtitlePreference` carries the last chosen language between films (normalised to the two-letter code, since Jellyfin says `eng` and Stash `en`); until the user has chosen, only a forced track shows. `SubtitleMenu` sits in the film transport and the video ornament (the Audio menu beside it picks the title's audio stream: `AudioStreamIndex` on the remux/transcode URL, see "Audio menu" in `hypnos-video-window.md`); the offset lives in the film's Sound and Picture window and the video Adjustments window. The tvOS generic player (`TVVideoPlayerView`, `AVPlayerViewController`, which plays every non-film Library title, Archer included) draws them in the controller's `contentOverlayView` (inside the picture, under the transport bar) and offers a Subtitles menu with the timing offset in `transportBarCustomMenuItems`; it had no subtitles at all before 2026-10-20. It also deselects AVKit's own legible option while one of ours shows, so a direct-play MP4's text track isn't drawn twice.

Placement: inside the aspect-fitted picture on flat players; **drawn into both eyes of the picture** while it is stereo (fake-3D or live 3D, video window and film player), because SwiftUI drawn over the stereo video plane never shows in front of it, whatever its z offset (device, 2026-10-07: the overlay at +20 pt was invisible), and the band hung under the window that replaced it sat at the window's depth, so the picture covered it from an angle. `StereoSubtitleFeeder` renders the cues showing with `RAVESubtitleText` into images at eye-pixel size and hands them to the engine; RAVEMedia's `StereoSubtitles.swift` places them in front of the content behind them (see RAVESDK `CLAUDE.md`). Their HDR white is `@AppStorage("subtitles.hdrWhiteNits")` (default 203 nits) and a user depth offset `subtitles.stereoDepth` (−1 nearer … 1 farther, ±0.004 of the eye's width per eye) moves them off the automatic depth. `subtitles.stereoStyle` = `belowPicture` brings back the band hung under the window (`SubtitleBand` in `PlayerOrnamentStack`, `subtitles.bandGap` below the edge, adjustable, default 20 pt). All three live in `StereoSubtitleSettings`, in the video Adjustments window and the film's Sound and Picture window while 3D is on; in the immersive stereo player, a view attachment on the eye→screen line at `ImmersiveVideoView.subtitleDistance` (4 m, untuned) scaled to the screen's angular width, because the film's pop-out comes far nearer than the 50 m screen. The MV-HEVC converter re-times frames from zero at a nominal frame rate, so a variable-frame-rate source can drift against its subtitles there.

Jellyfin 3D movies (`Video3DFormat`, e.g. `Movie.3D.HSBS.mkv`; mapped by `StereoscopicFormat(jellyfin:)` onto `LibraryItem.stereoFormat`) play as **live 3D**: the generic route hands the format to the video window (`LibraryPlaybackCoordinator.makeGalleryVideo` sets `isStereoscopic`/`stereoscopicFormat`), and an object-audio film's `FilmSession.stereoFormat` makes `FilmPlayerView` open in 3D with the eyes cropped from its sample-buffer tap (no depth model). A **Blu-ray disc** (Jellyfin `VideoType` Iso + `IsoType` BluRay, or a BDMV folder; `LibraryItem.isBlurayDisc`) with object audio opens in the film player with its picture decoded on the device: `MVCPictureSource` reads the raw ISO from `Videos/{id}/stream?static=true` with HTTP ranges through the local `vergence` package (`../../vergence`, product `VergenceApple`; MVC 3D via edge264) and feeds RAVEFilm's `FilmPictureSource` path; the plugin still supplies the audio, reading the disc through `vergence stream` (see `JellyfinPlugin/README.md`). Film time = playlist time + the first PlayItem's IN time, which is also the audio scene's `startSeconds`. Every Jellyfin disc goes to the film player (`playbackRoute`). When the plugin has no object audio for it (no plugin, or no TrueHD), the sound is the disc's own AC-3 (`DiscAudioSource`): a plain AC-3/E-AC-3 track, or the AC-3 core inside TrueHD, decoded through Apple's decoder by Vergence's `PlaylistAudioReader`. It plays as a RAVEFilm `FilmAudioSource` scene: five objects pinned at the 5.1 speaker positions plus an LFE bed, in 4 s segments read apart from the picture. The `filmDiscAudio` debug command switches a playing disc to it. A **disc image on the device** (`.iso` in the Local library) opens the same way, with no server: each platform's video-window root shows `LocalDiscHandoffView`, which calls `FilmSession.loadLocalDisc`, opens the film player and closes itself. Local film ids start with `local:` (`FilmSession.isServerItem`), so nothing is reported to Jellyfin. The disc's **PGS subtitles** come from the same reads as the picture (`DiscSubtitles`, fed by `MVCPictureSource`'s side PIDs) and are offered by `SubtitleSource.disc`. Cues carry a `RAVESubtitleImage`, decoded only while it shows, and the flat overlay and the stereo picture (`StereoSubtitle.frame`) place it where the disc put it. **A Jellyfin HLS remux reopens in a new play session after the background** (`VideoWindowModel.renewJellyfinStreamAfterBackground`, `JellyfinLibrary.renewedStreamURL`): a remux resumed mid-file cuts its segments at 6 s steps from the resume point while Jellyfin's playlist steps from the start of the file, so later segments sit 0–5 s from where the playlist puts them. Played straight through that is invisible; a segment reload (visionOS takes the decoder away during the low-light alert) shifted the player's clock, and subtitles with it, 3–5 s behind speech. A new job starts exactly at the first segment asked for; the stereo player opens it at the playhead (`takeStreamSwitchStart`) rather than playing from 0 and seeking, which stalled the picture until the next keyframe. The dev Jellyfin seeds `Twin Horizon (2020).3D.HSBS.mp4` (embedded mov_text + sidecar French SRT), and the macOS `-LibraryHarness` prints each 3D movie's format; sidecar English/Spanish SRTs sit on the Atmos demo.

## Library downloads (offline)

`Services/Library/Offline/`. A Download button sits top-right on every Library detail page (`LibraryDownloadButton`), the same choices are in each lockup's context menu (`LibraryDownloadMenuItems`), and the Library home's toolbar opens `LibraryDownloadsView`. tvOS has none of it (`LibraryDownloads.isSupported`: its storage is a purgeable cache).
- **Permission is enforced client-side.** Jellyfin's `CanDownload` (asked for on every list via `Fields`) and the account's `Policy.EnableContentDownloading` grey the button out, and pressing it says why. `Items/{id}/Download` answers 403 for such an account, but the `stream.mp4` remux does not (measured on the dev instance with a `nodownloads` user), so the job checks `canDownload` itself before any request.
- **What gets downloaded** (`JellyfinLibrary.downloadPlan`): an AVFoundation-playable MP4/MOV as the original file; anything else (MKV, WebM) as a progressive server remux to fragmented MP4 (video copied when H.264/HEVC, AAC 5.1; no Content-Length, so progress is against the source size); an object-audio film as a `FilmPackage`, the plugin's own video segments joined into one MP4 plus its whole audio scene (`POST Prepare`, then every segment), played offline by `FilmServerClient(itemID:offline:)` through the streamed code path; a Blu-ray disc as its ISO, plus the package's audio when the plugin has objects.
- **Where:** the media file and its WebVTT subtitle sidecars go to `Documents/Videos/Jellyfin/` (Files app and Local library); metadata, artwork, segments and the package go to `Application Support/LibraryOffline/` (`LibraryOfflineStore`, `index.json`). A file deleted in Files drops its download at the next launch. Opening a film-player download from the Local library hands it to the film player (`GalleryVideo.opensInFilmPlayer`), so its object audio survives.
- **Offline behaviour lives in `JellyfinLibrary`**, so screens and players need no changes: an unreachable server (`isUnreachable`) makes home/item/seasons/episodes/Next Up/next episode answer from `LibraryOfflineCatalog`; a download always plays from the device (`playbackRoute`), with subtitles, segments and artwork from the device. Progress reports also update the record's local position; one the server didn't take sets `needsSync`, and `LibraryDownloads.syncPendingWatchState` sends it (`POST UserItems/{id}/UserData`) at launch and when the server answers again.
- The media transfer is a background `URLSession` (draft records under `pending/` file a transfer that finishes in a later launch); the object-audio package is fetched while the app runs and resumes from `video-ranges.json` on retry.
- `-LibraryDownloadHarness` (macOS DEBUG, `Support/LibraryDownloadHarness.swift`) downloads one title of each kind from the dev Jellyfin, plays each back from the device, serves the Library from an unreachable server, syncs offline progress and checks a downloads-disabled account (`HYPNOS_HARNESS_NODL_TOKEN`/`_USER`).
